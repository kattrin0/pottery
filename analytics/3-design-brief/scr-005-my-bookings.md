# Требования на дизайн · SCR-005 · Мои записи (десктоп)
ID: SCR-005 · Тип: Экран · Зона: АЗ · Приоритет: Critical
Версия: 0.2 · Дата: 2026-07-05
Источники: [Foundations](00-foundations.md) · [BR-005] · [FR-023] · [US-012…014] · [UC-005, UC-006] · [data-model]
Сквозные правила – в `00-foundations.md`.

## 1. Назначение и контекст
Список записей клиента. На десктопе – табличное представление (или сетка карточек) с возможностью фильтрации по статусу (предстоящие/прошедшие). Вкладка «Мои записи» – в верхней навигации (хедер).
Даёт клиенту контроль над своими записями – отдельно предстоящими и прошедшими.

## 2. Пользователь и цель
Роль: Клиент.
Цель: быстро увидеть свои предстоящие записи, проверить детали, при необходимости отменить.

## 3. Навигация
Входящие:
- Вкладка «Мои записи» в хедере.
- BS-002 (Подтверждение записи) – кнопка «Мои записи».
Исходящие:
- Клик по строке → SCR-006 «Детали записи».
- Вкладка «Расписание» → SCR-002.
- Иконка профиля → SCR-007.
- Empty state → SCR-002 («Записаться на занятие»).

Каркас: хедер с вкладками, основная область. Таб-бар отсутствует.

## 4. Контент-инвентарь
### 4.1 Карточка/строка записи
| Поле | Источник | Назначение |
|------|----------|------------|
| status | booking | Бейдж: active → «активна», cancelled → «отменена», late_cancel → «поздняя отмена», cancelled_by_workshop → «отменено мастерской» |
| start_at | slot | Дата и время – крупно |
| program.name | slot → program | Название программы |
| master.name | slot → master | Имя мастера |
| price | slot / booking | Цена |
| use_rental | booking | «Свои инструменты» / «Прокат» |

### 4.2 Разделение списка
Предстоящие – только активные записи (status = active) с start_at в будущем.
Прошедшие – записи с start_at в прошлом И все отменённые (cancelled / late_cancel /
cancelled_by_workshop) независимо от даты старта. Отменённая запись с будущим стартом – в «Прошедшие».
Сортировка прошедших – по убыванию даты старта (свежие сверху).

## 6. Компоненты и поведение
- Переключатель «Предстоящие / Прошедшие»: сегмент-контрол вверху. По умолчанию – «Предстоящие».
- Строка таблицы – кликабельна целиком, тап → SCR-006.
- Бейдж статуса: текст + форма, не только цвет.
- Кнопка обновления (или автоматическое обновление).

## 7. Состояния экрана
| Состояние | Содержимое / Поведение |
|-----------|------------------------|
| Loading | Скелетоны строк/карточек |
| Content | Список записей, разделённый на Предстоящие / Прошедшие |
| Empty (нет записей) | «У вас пока нет записей» + «Записаться на занятие» → SCR-002 |
| Empty в «Предстоящие» | «Нет предстоящих записей» + «Записаться на занятие» |
| Error | «Не удалось загрузить список» + «Повторить» |

## 8. Валидации и микрокопия
Доступ к данным: клиент видит только свои записи (NFR-012, foundations §8.2).
| status | Текст бейджа |
|--------|--------------|
| active | «активна» |
| cancelled | «отменена» |
| late_cancel | «поздняя отмена» |
| cancelled_by_workshop | «отменено мастерской» |

## 9. Доступность и адаптивность (десктоп)
- Крупные строки с большой тач-зоной (32px).
- Бейджи статусов – текст + форма, читаемы.
- Даты/время – понятный формат.
- Переключатель и строки имеют доступные имена для screen reader.
- Адаптив: на мобильных таблица превращается в карточки.

## 10. Критерии приёмки дизайна
AC-001 — Разделение на предстоящие и прошедшие
  Дано: у клиента есть записи с разными датами и статусами
  Когда: открыт SCR-005
  Тогда: записи разделены на группы «Предстоящие» и «Прошедшие»
  И по умолчанию отображаются предстоящие
  И в «Предстоящие» попадают только активные записи с будущим стартом

AC-002 — Отменённая запись с будущим стартом – в «Прошедшие»
  Дано: запись отменена, но старт в будущем
  Когда: открыт SCR-005
  Тогда: запись в группе «Прошедшие»

AC-003 — Статус записи
  Дано: запись имеет статус
  Когда: клиент видит строку
  Тогда: показан бейдж со статусом текстом и формой

AC-004 — Пустой список
  Дано: нет записей
  Когда: открыт SCR-005
  Тогда: заглушка «У вас пока нет записей» + «Записаться на занятие»

AC-005 — Только свои записи
  Дано: в системе есть записи разных клиентов
  Когда: открыт SCR-005
  Тогда: видны только собственные записи

AC-006 — Переход к деталям
  Дано: показана строка
  Когда: клик по строке
  Тогда: открывается SCR-006

## 11. Решения
| # | Решение |
|---|---------|
| 1 | Отменённые записи – всегда в «Прошедшие» (§4.2). |
| 2 | Сортировка прошедших – по убыванию даты старта. |
| 3 | Empty по секциям – отдельная подсказка в «Предстоящие», если есть только прошедшие. |
| 4 | Глубина истории – параметр данных, в MVP грузится вся доступная история. |
| 5 | На десктопе – табличное представление. |
