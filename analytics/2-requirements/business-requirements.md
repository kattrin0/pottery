# Бизнес-требования (BR)

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| BR-001 | Клиент должен иметь возможность **самостоятельно** просматривать расписание и бронировать занятия без ручной записи через Instagram/ежедневник | Must |
| BR-002 | Цифровизация должна **снизить операционную нагрузку** владельца мастерской | Must |
| BR-003 | Решение должно уменьшить последствия ручной записи: двойные бронирования, путаницу в выходные, простой ресурсов (мест, глины, мастеров) | Should |
| BR-004 | **Администрирование** расписания, мастеров и слотов остаётся в **существующей инфраструктуре** и не входит в текущую поставку | Won't |
| BR-005 | MVP must-have: **расписание, запись, отмена, фильтр по программе** | Must |
| BR-006 | Одна бронь соответствует **одному клиенту и одному месту** в слоте; подтверждение — **сразу** после успешного ответа API, без ручной модерации | Must |
| BR-007 | Оплата в MVP — **офлайн** (наличные / перевод); клиент показывает цены, платёжный шлюз не подключается | Must |
| BR-008 | При отмене клиентом: **не позднее 2 ч** до начала — без штрафа; **менее 2 ч** — штраф в % от стоимости (текущее значение настроек: 50%); параметры приходят из бэкенда | Must |
| BR-009 | При форс-мажорной отмене мастерской бронь клиента переходит в статус **«Отменено мастерской»** с причиной; повторная запись на тот же слот **запрещена** | Should |
| BR-010 | Клиент после посещения оставляет **оценку мастера 1–5 звёзд** для оценки качества работы мастеров | Should |
| BR-011 | Клиент получает **напоминания о записи** и **push при отмене мастерской** (Web Push в браузере) | Should |
| BR-012 | **Лист ожидания** не предусмотрен | Won't |
| BR-013 | **Программа лояльности** не входит в MVP | Won't |
| BR-014 | В текущей поставке реализуется только роль **Клиент**; админка и интерфейс мастера — в существующей инфраструктуре | Won't |
| BR-015 | Гарантия «0 двойных броней», транзакционность и взыскание штрафа офлайн — **вне скоупа клиентской поставки**; клиент полагается на ответы API | Won't |
