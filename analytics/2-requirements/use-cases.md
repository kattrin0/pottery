## UC-001 Аутентификация клиента

**Актор:** Клиент  
**Приоритет:** Must

**Предусловия:** клиент не аутентифицирован.

**Основной поток:**
1. Клиент открывает экран входа.
2. Вводит номер телефона.
3. Получает и вводит SMS-код.
4. API верифицирует код и выдаёт сессию/токен.
5. Клиент получает доступ к функциям приложения.

---

## UC-002 Просмотр расписания

**Актор:** Клиент  
**Приоритет:** Must

**Предусловия:** клиент аутентифицирован.

**Основной поток:**
1. Клиент открывает расписание.
2. Система загружает слоты на **7 дней** по умолчанию.
3. Слоты отображаются **отсортированными по дате и времени**.
4. В карточке видны: время, программа, мастер (с фото), свободные места, цена, длительность, описание, адрес, статус.

**Альтернативные потоки:**
- **2a.** Слот полностью занят — отображается с пометкой **«мест нет»**.
- **2b.** Слотов на период нет — empty state **«Пока нет доступных занятий»**.

## UC-003 Фильтрация расписания

**Актор:** Клиент  
**Приоритет:** Must

**Предусловия:** клиент на экране расписания.

**Основной поток:**
1. Клиент выбирает **программу** (новички / круг) и/или **диапазон дат** (до месяца).
2. Система показывает отфильтрованный список слотов.

**Альтернативный поток:**
- **2a.** Нет подходящих слотов — empty state «Пока нет доступных занятий».

---

## UC-004 Бронирование занятия

**Актор:** Клиент  
**Приоритет:** Must

**Предусловия:** клиент аутентифицирован; слот доступен для записи (не отменён мастерской).

**Основной поток:**
1. Клиент выбирает слот.
2. Указывает **свои инструменты** или **прокат**.
3. Видит **цену** (и доплату за прокат) из API.
4. Подтверждает бронь на **одного человека**.
5. API атомарно резервирует место.
6. Клиент видит статус **подтверждена сразу**.

**Альтернативный поток:**
- **5a.** Мест нет — запись недоступна или API возвращает отказ; клиент видит сообщение (например, «мест уже нет»).

## UC-005 Отмена брони клиентом

**Актор:** Клиент  
**Приоритет:** Must

**Предусловия:** у клиента есть активная бронь.

**Основной поток (≥ 2 ч до начала):**
1. Клиент инициирует отмену.
2. Система показывает, что отмена **без штрафа**.
3. Клиент подтверждает.
4. API обрабатывает отмену; место освобождается.

**Альтернативный поток (< 2 ч до начала):**
1. Клиент инициирует отмену.
2. Система показывает **% штрафа** и **расчётную сумму** из API.
3. Клиент подтверждает отмену со штрафом.
4. API обрабатывает отмену.

## UC-006 Отображение отмены мастерской

**Актор:** Клиент (получатель); Мастерская (инициатор — вне скоупа клиента)  
**Приоритет:** Should

**Триггер:** слот отменён в существующей инфраструктуре (форс-мажор).

**Основной поток:**
1. Бронь клиента **не удаляется**, получает статус **«Отменено мастерской»** с **причиной**.
2. Клиент видит статус и причину в приложении.
3. Клиент получает **Web Push**.
4. Повторная запись на этот слот **недоступна**.

---

## UC-007 Оценка мастера

**Актор:** Клиент  
**Приоритет:** Should

**Предусловия:** клиент посетил занятие; бронь в статусе, допускающем оценку.

**Основной поток:**
1. Клиент открывает форму оценки.
2. Выставляет **1–5 звёзд**.
3. API сохраняет оценку с привязкой к брони.

---

## UC-008 Подписка на уведомления

**Актор:** Клиент  
**Приоритет:** Should

**Основной поток:**
1. Клиент разрешает **Web Push** в браузере.
2. Система регистрирует подписку.
3. Клиент получает **напоминания о записи** и **push при «Отменено мастерской»**.
