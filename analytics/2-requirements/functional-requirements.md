# Функциональные требования (FR)

## Аутентификация

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| FR-001 | Система предоставляет **экран входа** с вводом телефона и SMS-кода | Must |
| FR-002 | Система выполняет **аутентификацию** через API (верификация телефона, получение сессии/токена) | Must |

## Просмотр расписания

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| FR-003 | Клиент **читает и отображает слоты** из API | Must |
| FR-004 | По умолчанию отображаются слоты на **ближайшие 7 дней** | Must |
| FR-005 | Клиент может **фильтровать слоты по дате** — до **месяца** вперёд | Should |
| FR-006 | Клиент может **фильтровать слоты по программе** (новички / круг) | Must |
| FR-007 | Слоты по умолчанию **сортированы по дате и времени** | Should |
| FR-008 | Карточка слота отображает: время, программу, мастера, свободные места, цену, длительность, описание, адрес, статус | Must |
| FR-009 | **Полностью занятые** слоты отображаются с пометкой **«мест нет»** | Should |
| FR-010 | При отсутствии слотов на период показывается empty state **«Пока нет доступных занятий»** | Should |
| FR-011 | Клиент **читает и отображает программы** занятий из API | Must |
| FR-012 | Клиент **читает и отображает мастеров** (включая фото), привязанных к слотам | Should |

## Бронирование

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| FR-013 | Клиент оформляет **бронь на одного человека** (одна бронь = одно место) | Must |
| FR-014 | При бронировании клиент выбирает **«свои» инструменты и фартук** или **прокат** | Should |
| FR-015 | До записи отображается **цена занятия** и **доплата за прокат** (из API) | Should |
| FR-016 | Отображаются **тариф проката** и **свободный прокатный фонд** из API | Should |
| FR-017 | После запроса брони клиент отображает статус **подтверждена сразу** при успешном ответе API | Must |
| FR-018 | При отсутствии мест запись **недоступна** или API возвращает отказ | Must |
| FR-019 | При отказе API (нет мест) клиент показывает **понятное сообщение** (например, «мест уже нет») | Must |

## Отмена

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| FR-020 | Клиент может **запросить отмену** своей брони | Must |
| FR-021 | При отмене клиент отображает **% штрафа** и **расчётную сумму** из API | Must |
| FR-022 | При поздней отмене (< 2 ч) перед отправкой запроса показывается **подтверждение с отображением штрафа** из API | Must |
| FR-023 | Клиент отображает статус брони **«Отменено мастерской»** и **причину отмены** из API | Should |
| FR-024 | Для слота со статусом «отменён мастерской» **повторная запись запрещена** | Should |

## Оценка и уведомления

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| FR-025 | После проведённого занятия клиент может поставить **оценку мастеру 1–5 звёзд** | Should |
| FR-026 | Клиент запрашивает **разрешение на Web Push** в браузере | Should |
| FR-027 | Клиент получает **напоминания о записи** через Web Push | Should |
| FR-028 | Клиент получает **Web Push при статусе «Отменено мастерской»** | Should |

## Обработка ошибок

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| FR-029 | Клиент **обрабатывает ответы и ошибки API** и показывает пользователю понятные сообщения | Must |
