# Нефункциональные требования (NFR)

## Удобство использования

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| NFR-001 | Интерфейс — **адаптивный веб-сайт**: корректная работа на экранах от смартфона до десктопа | Must |
| NFR-002 | Один и тот же сайт открывается в **браузере** на телефоне, планшете и компьютере, без нативной оболочки | Must |
| NFR-003 | При ошибках и отказах API пользователь видит **понятные сообщения** (например, «мест уже нет»), а не технические детали | Must |

## Совместимость

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| NFR-004 | Целевые браузеры — актуальные **Chrome, Safari, Firefox, Edge** (десктоп и мобильные) | Must |
| NFR-005 | Сайт работает как **веб-приложение в браузере** (SPA), без установки из магазина приложений | Must |

## Интеграция

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| NFR-006 | Взаимодействие с бэкендом — через **HTTP REST API** (или эквивалент) по контракту **OpenAPI** | Must |
| NFR-007 | Существующий бэкенд мастерской — **black-box**, источник истины; детали реализации, транзакционность и внутренние модели **не входят в ответственность клиента** | Must |
| NFR-008 | Каноническая схема данных текущей поставки — **контракт OpenAPI** клиентского API | Must |

## Поддерживаемость и архитектура

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| NFR-009 | Клиент **не дублирует** серверную бизнес-логику (лимит мест, расчёт штрафа, доступность слота); полагается на ответы API | Must |
| NFR-010 | Параметры отмены (порог в часах, % штрафа) **не захардкожены** в клиенте — получаются из API | Must |

## Технологический стек

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| NFR-011 | Клиентская часть реализуется как **Vue.js SPA** | Must |
| NFR-012 | Браузерные уведомления реализуются через **Web Push** с **Service Worker** | Should |

## Ограничения проекта

| ID | Формулировка | Приоритет |
| --- | --- | --- |
| NFR-013 | Срок поставки — **к началу осеннего сезона (~2 месяца)** | Must |
| NFR-014 | **Ограниченный бюджет**; приоритет — MVP, расширения отложены | Must |
| NFR-015 | Проект **учебный/тестовый**; исторических данных и легаси-схемы нет; **миграция и backfill** старых данных не требуются | Should |
